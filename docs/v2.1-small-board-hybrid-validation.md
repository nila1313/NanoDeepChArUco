# v2.1 Small-Board Hybrid Validation

## Scope

This validation covers the addition of a DeepChArUco configuration for the
small 5x6 ChArUco board:

- Dictionary: DICT_6X6_250
- Board: 5 x 6 squares
- ChArUco IDs: 20
- Marker/square ratio: 0.6666666667
- DeepChArUco input size: 320 x 240

Feature commit:

`5c99f29 Add small-board DeepChArUco configuration`

The validation focuses on detection coverage and regression behavior.
It does not claim calibration-accuracy or reprojection-error improvement.

---

## Pair 07: difficult small-board case

Dataset:

- Left: `CADDX000021_left.MP4`
- Right: `CADDX000019_right.MP4`
- Sampling step: 20
- Offsets: `[0, +7]`
- Shared logical slots: 132
- Left physical frames: 0 ... 2620
- Right physical frames: 7 ... 2627

A usable frame is defined as having at least 5 finite ChArUco corners.

### Nano release baseline

| Metric | Result |
|---|---:|
| Left usable | 57 / 132 |
| Right usable | 27 / 132 |
| Shared usable | 27 / 132 |
| Shared coverage | 20.5% |

| Right median corners | 0.0 |

### Small-board Hybrid

| Metric | Result |
|---|---:|
| Left usable | 69 / 132 |
| Right usable | 65 / 132 |
| Shared usable | 61 / 132 |
| Shared coverage | 46.2% |
| Left median corners | 5.5 |
| Right median corners | 3.5 |

### Direct payload comparison

The Nano and Hybrid runs used identical:

- logical detection indices
- physical frame indices
- stereo offset semantics
- sampling grid

Shared-slot change:

| Metric | Count |
|---|---:|
| Nano shared slots retained | 27 |
| Newly recovered shared slots | 34 |
| Nano shared slots lost | 0 |
| Net gain | +34 |

Shared coverage increased from **20.5% to 46.2%**.

This corresponds to approximately **2.26x as many usable shared stereo
observations**.

Corner-count comparison:

- Left was unchanged on 94 frames
- Left was worse on 0 frames

## Pair 07 recovery-stage audit

The 34 newly recovered stereo slots were reprocessed with Hybrid status
logging.

### Left camera

| Hybrid status | Slots |
|---|---:|
| RAW_NANO | 6 |
| GAMMA_NANO | 8 |
| DEEP_NANO_H | 15 |
| DEEP_SELF | 5 |

### Right camera

| Hybrid status | Slots |
|---|---:|
| DEEP_NANO_H | 3 |
| DEEP_SELF | 31 |

The weak right camera required a DeepChArUco stage on all 34 newly
recovered shared slots.

Most right-camera recovery was performed by `DEEP_SELF`.

`DEEP_NANO_H` indicates the homography-assisted Hybrid path. In some
individual frames this path may validate or preserve corners obtained from
Nano/gamma processing even when no additional Deep corner is ultimately
accepted.

`10 passed`

---

## Conclusion

The small-board DeepChArUco configuration enables the existing Hybrid
pipeline to recover substantially more usable stereo observations on the
difficult Pair 07 dataset.

At the same time, the existing Nano-only behavior is reproduced exactly on
Pairs 01, 03, and 05.

The results support enabling small-board Hybrid detection while preserving
the stable v2.0 Nano path.
